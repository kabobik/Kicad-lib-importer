# Кнопка восстановления схемы по меди

ActionPlugin для PCB Editor: **Восстановить схему по меди**. Появляется в меню
**Инструменты → Внешние плагины** и на панели инструментов с иконкой проводников.

## Установка (Linux)

Из корня репозитория:

```bash
./scripts/install_connectivity_recovery_plugin.sh
```

Установщик проверяет системный Python 3.11+ с `pcbnew` и наличие `kicad-cli`, затем
создаёт символическую ссылку на каталог плагина. Путь по умолчанию:

```text
${XDG_DATA_HOME:-~/.local/share}/kicad/<major.minor>/scripting/plugins/connectivity_recovery_plugin
```

Версия берётся из `kicad-cli version`; неизвестная версия вызывает ошибку вместо
установки в произвольную папку. Для ручного выбора назначения используйте
`KICAD_PLUGIN_DIR`. При нескольких Python можно задать `KICAD_RECOVERY_PYTHON`
как путь к исполняемому файлу Python с модулем `pcbnew`; эта переменная должна быть
доступна и при запуске KiCad. Плагин не использует `sys.executable` встроенного
интерпретатора, поскольку он может указывать на `pcbnew`, а не на Python.

Повторная установка той же ссылки допустима. Чужая папка или ссылка не заменяется.
`sudo` не нужен. После установки перезапустите редактор платы. Если кнопка скрыта,
проверьте её видимость в настройках Action Plugins; пункт внешних плагинов остаётся
доступен. При перемещении репозитория переустановите ссылку.

## Работа

1. Сохраните плату. Сохраните и закройте редактор схемы: после замены файла его
   нужно открыть заново, чтобы не сохранить поверх результата старую версию из памяти.
2. Откройте кнопку восстановления в редакторе платы.
3. Путь текущей платы подставится автоматически; одноимённая схема рядом — если
   она существует. Можно выбрать другие сохранённые файлы.
4. Укажите папку резервной копии. По умолчанию это
   `recovery/<имя платы>-YYYYMMDD-HHMMSS/` рядом с рабочей платой. Каждый запуск
   сохраняет отдельную прежнюю версию; при совпадении времени добавляется номер.
5. Задайте длину проводов (2,5 мм), размер текста (1,27 мм) и префикс цепей (`REC`).
6. Нажмите **Восстановить**. Рабочая схема будет заменена результатом. Флажок
   назначения цепей в рабочей PCB по умолчанию включён.
7. Откройте рабочую схему по её обычному пути. Папка `recovery` содержит прежние
   файлы для отката, а не новую рабочую схему.

Окно остаётся отзывчивым. Извлечение и подготовку можно остановить; дочерние
процессы при этом завершаются, рабочие файлы остаются прежними. Короткий финальный
этап резервного копирования и записи завершается целиком, включая откат при ошибке;
запрос остановки или закрытия окна во время этого этапа не обрывает замену файлов.
В папке копии после отмены могут остаться промежуточные отчёты. Для повторного
запуска автоматически предлагается новый путь, если использовался путь по умолчанию.

Подготовленный результат сначала проверяется во временной папке. Перед заменой
сверяются хэши исходных и подготовленных файлов, затем исходные схема, плата и
существующий `.kicad_pro` сохраняются в папку резервной копии. При ошибке записи
уже заменённые рабочие файлы возвращаются к прежнему содержимому. Отключение питания
между записями двух файлов не является атомарной транзакцией; копии остаются для отката.

Если открытая плата имеет несохранённые изменения, её нужно сначала сохранить.
После записи PCB назначения цепей синхронизируются в памяти текущего PCB Editor
по UUID объектов; геометрия не меняется. Файл перечитывается через нативный
`PCB_IO_MGR.Load`, поскольку `LoadBoard` для активного проекта возвращает старую
плату редактора. Соответствие назначений проверяется после обновления. Если синхронизация не удалась, окно
покажет, что плату нужно переоткрыть без сохранения старой версии. Редактор схемы
нужно закрыть перед запуском: API плагина PCB не перезагружает его документ.

Для отката закройте редакторы и скопируйте сохранённые `.kicad_sch` и `.kicad_pcb`
из выбранной папки `recovery` обратно по рабочим путям. `.kicad_pro` также сохранён
для восстановления настроек, но сам плагин рабочие настройки не меняет.

## Файлы и границы

- `connectivity.json`, `connectivity.csv` — результат извлечения физической связности.
- `.kicad_sch`, `.kicad_pcb`, существующий `.kicad_pro` в папке `recovery` — исходники
  до применения; обновлённая схема и плата находятся по первоначальным рабочим путям.
- `validation.json`, `netlist.xml` — нативная проверка цепей.
- `recovery.log` — последние 64 строки вывода дочерних команд, до 4096 символов
  на строку. Журнал ограничен по размеру, один файл на выбранный каталог результата.

При расхождениях схема и плата сохраняются, окно показывает **«Готово — требуется
проверка инженером»** и перечисляет оставшиеся проблемы с выводами. Совмещённые
выводы, старые связи и метки не блокируют остальное восстановление. Полное
совпадение с медью и завершение обработки — разные признаки в `validation.json`:
`verified` и `completed`; `applied_in_place` подтверждает замену рабочих файлов,
`working_schematic`, `working_board`, `backup_directory` указывают точные пути.
При конфликте островков зоны назначения PCB сохраняются
исходными; это также видно в окне. Инженер проверяет и доводит полученный проект.

При ошибке чтения/записи или неподдерживаемом входе извлечённая таблица и журнал
сохраняются для просмотра. Пользователь сам выбирает, какие каталоги результатов
сохранять или удалять; автоматического фонового накопления истории нет.

Плагин — только интерфейс к [основной утилите](../../tools/connectivity_recovery/README.md).
Её ограничения, включая один лист схемы и запрет проектных исключений, сохраняются.
MCP, EDA Core, перезаливка зон и повторная реализация графа соединений не используются.

## Владельцы кода

- `main.py`, `__init__.py`: регистрация действия и иконка. Встроенный `wx.AppConsole`
  без `GetTopWindow` поддерживается: диалог открывается без родительского окна.
- `ui.py`: поля формы, состояние окна и отображение результата.
- `runner.py`: фоновый запуск `extract` и `apply` во временную папку, отмена,
  вызов канонической установки результата и ограниченный журнал.
- `tools/connectivity_recovery/cli.py::install_prepared_recovery` и `publish`:
  проверка хэшей, резервное копирование, замена рабочих файлов и откат ошибок записи.
- `tools/connectivity_recovery/board.py::sync_editor_net_assignments`:
  перенос сохранённых назначений цепей в память открытой платы без записи геометрии.
- `scripts/lib/kicad_plugin_installer.sh`: общий установщик ссылок ActionPlugin;
  используется также существующим установщиком генератора разъёмов.
- `tools/connectivity_recovery/`: единственный владелец восстановления и проверки CAD-файлов.

Иконка: исходный `icon.svg`, результат `icon.png`. Пересоздание:

```bash
rsvg-convert -w 24 -h 24 -o plugins/connectivity-recovery/connectivity_recovery_plugin/icon.png \
  plugins/connectivity-recovery/connectivity_recovery_plugin/icon.svg
```

## Проверки

```bash
PYTHONDONTWRITEBYTECODE=1 python3 -m unittest discover -s tests -p test_connectivity_recovery_plugin.py -v
# Дополнительно, из графической сессии (диалог не показывается):
KICAD_TEST_GUI=1 PYTHONDONTWRITEBYTECODE=1 python3 -m unittest discover -s tests -p test_connectivity_recovery_plugin_ui.py -v
```

Тесты проверяют настоящую цепочку CLI на временных проектах, пробелы и Unicode
в путях, замену рабочих файлов с предупреждениями, точность резервных копий,
повторный запуск без дубликатов, отмену дочерних процессов,
определение версии, повторную установку и защиту чужой установки. Отдельно
проверяется вызов `Run()` со встроенным `AppConsole` без `GetTopWindow`, обычным
GUI-приложением и освобождение диалога при ошибке.
GUI-тест проверяет параметры, фоновое завершение, показ предупреждений и кнопки результата,
а также синхронизацию старой открытой платы с новым файлом и сохранение цепей после Ctrl+S. Загрузку
действия в панель настоящего PCB Editor проверяют после его перезапуска.
