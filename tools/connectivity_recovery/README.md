# Восстановление соединений по меди

Утилита `scripts/recover_connectivity.py` выполняет файловый процесс без MCP,
EDA Core и запущенного редактора KiCad:

1. `extract`: медь PCB → физические группы → JSON и читаемый CSV.
2. `apply`: JSON → короткие провода и локальные метки существующей схемы.
3. `verify`: сравнение полного состава цепей схемы с физическими группами.

Состав цепей определяется только медью. Нет проектных исключений, угадывания
функций выводов или автоматического объединения раздельных физических групп.
Изолированные выводы не получают искусственных соединений.
Инструмент снимает рутину: выполняет доступную работу, сохраняет результат и
перечисляет оставшиеся расхождения для инженера. Совмещённые выводы, старые
соединения и неоднозначные метки не требуют полного совпадения схемы с медью
для записи результата. Проверка и доводка схемы остаются за пользователем.

## Владелец реализации

- `board.py`: нативная связность `pcbnew`, таблица групп и изменение полей сетей PCB.
- `schematic.py`: координаты выводов, провода/метки и отчёт расхождений через
  `kicad-cli`; отдельная команда `verify` проверяет полное совпадение.
- Совпадение электрических точек выявляется по координатам всех выводов,
  без проверок конкретных обозначений компонентов.
- `cli.py`: команды, параметры, временная проверка и публикация результатов;
  `install_prepared_recovery` устанавливает подготовленные файлы с резервной копией
  для GUI, используя тот же `publish` для замены и отката.
- `board.py::sync_editor_net_assignments`: синхронизация назначений цепей открытой
  платы по UUID после файловой установки; последующее сохранение не вернёт старые цепи.
  Для чтения записанного файла используется `PCB_IO_MGR.Load`: обычный `LoadBoard`
  внутри PCB Editor возвращает уже открытую плату из памяти. После обновления
  проверяется соответствие имён цепей всех площадок, дорожек, переходов и зон.
- `tools/kicad_sexpr.py`: общий разбор с сохранением исходного текста; используется
  также генератором символов разъёмов. Документы целиком не пересериализуются.

Проверено на KiCad 10.0.8. Нужны системный Python 3.11+ с модулем `pcbnew` и
`kicad-cli` в PATH. Дополнительные pip-пакеты не требуются. Обычный изолированный
venv может не видеть установленный вместе с KiCad модуль `pcbnew`.

## Кнопка в редакторе платы

[GUI-плагин](../../plugins/connectivity-recovery/README.md) запускает те же команды
в отдельном процессе. Установка: `./scripts/install_connectivity_recovery_plugin.sh`,
затем перезапуск PCB Editor. Окно подставляет текущую плату, предлагает параметры,
показывает ход работы и заменяет рабочую схему результатом. Исходные схема,
плата и настройки сохраняются в `recovery/<имя>-<дата-время>/` для отката.
Если включено назначение цепей PCB, обновляются файл платы и назначения в памяти
редактора. Сохраните плату и закройте сохранённую схему перед запуском, затем
откройте её по прежнему рабочему пути. Копия в `recovery` — прежняя версия.
Файловый CLI ниже сохраняет явный выбор `--output-dir` / `--in-place`.

## Использование

Из корня репозитория:

```bash
# 1. Извлечь цепи. Плата не изменяется.
python3 scripts/recover_connectivity.py extract /path/panel.kicad_pcb \
  --output /tmp/panel-nets.json

# 2. Создать проверенные копии схемы и платы в новом каталоге.
python3 scripts/recover_connectivity.py apply \
  --board /path/panel.kicad_pcb \
  --schematic /path/panel.kicad_sch \
  --nets /tmp/panel-nets.json \
  --output-dir /path/recovered \
  --write-pcb

# 3. Независимо повторить проверку.
python3 scripts/recover_connectivity.py verify \
  --board /path/recovered/panel.kicad_pcb \
  --schematic /path/recovered/panel.kicad_sch \
  --nets /tmp/panel-nets.json
```

`extract` записывает рядом `panel-nets.csv` с колонками: сеть, компонент, вывод,
UUID площадки, физическая группа. JSON — вход `apply`; CSV предназначен для
просмотра. В JSON разрешено менять только `name` групп. Состав групп и UUID
повторно сверяются с платой; изменение входной PCB требует нового `extract`.
Существующие явные имена цепей схемы сохраняются. Имена JSON применяются для
новых цепей, а не для переименования уже соединённых и подписанных цепей.

`--write-pcb` назначает сетям PCB имена из netlist для совпавших групп. Для групп
с расхождениями берутся отдельные имена из таблицы меди; при коллизии добавляется
числовой суффикс. Лишняя связь схемы не переносится в назначения цепей платы.
Без этого флага копируется исходная плата с прежними назначениями.
Форма меди, площадки, дорожки, переходы, изображения и сохранённая заливка
сохраняются; изменяются только поля сетей и, для старого формата, их определения.

## Настройки

| Настройка | По умолчанию | Где задаётся |
| --- | --- | --- |
| Длина провода от вывода | 2,5 мм | `apply --wire-length 2.5` |
| Размер текста метки | 1,27 мм | `apply --label-size 1.27` |
| Префикс новых имён | `REC` | `extract --prefix REC` |
| Выходные CAD-файлы | требуется явный выбор | `--output-dir` либо `--in-place` |
| Назначение сетей на PCB | выключено | `apply --write-pcb` |
| Дополнительный JSON-отчёт об успехе | stdout | `--report /path/result.json` |
| Исполняемый файл KiCad CLI | `kicad-cli` | `apply/verify --kicad-cli /path/kicad-cli` |

Можно использовать [settings.example.toml](settings.example.toml):

```toml
[drawing]
wire_length_mm = 2.5
label_size_mm = 1.27

[naming]
prefix = "REC"
```

Передайте `--config /path/settings.toml` командам `extract` и `apply`.
Параметры командной строки имеют приоритет. Неизвестные параметры конфигурации,
нулевые/отрицательные длины и нечисловые значения отклоняются.

Провод идёт от электрической точки вывода наружу из символа с учётом поворота,
зеркала, номера секции и варианта изображения. Координаты существующих объектов
не округляются и не перемещаются. Автоматического выбора другой сетки и
перекомпоновки схемы нет. Конечная электрическая связность проверяется самим
KiCad; визуальное наложение текста следует проверять в редакторе.

## Запись и повторный запуск

По умолчанию следует использовать `--output-dir` с новым каталогом. Там будут
схема, плата, существующий `.kicad_pro`, `validation.json` и `netlist.xml`.
Подготовка и проверка идут во временном каталоге. При несовпадении цепей файлы
всё равно записываются, код завершения `apply` — 0: выполнена доступная работа.
Отчёт содержит:

- `completed: true` — результат создан;
- `verified` — совпадает ли состав цепей с медью, а не готовность проекта к производству;
- `warnings` — пояснения и действия для инженера, включая координаты совмещённых выводов;
- `topology_mismatches` — ожидаемые выводы каждой группы и фактические связи схемы;
- `net_names` — выбранные назначения для PCB; `schematic_net_names` — имена из схемы;
- `pcb_net_fields_requested` и `pcb_net_fields_updated` — запрашивалось и выполнено ли
  назначение цепей в PCB.

Команда `verify` остаётся строгой независимой проверкой: при расхождении возвращает
код 2 и ничего не меняет. Нечитаемые файлы, устаревшая таблица, несовместимые UUID,
неподдерживаемая структура и ошибки записи по-прежнему завершают `apply` кодом 2.
Диагностика таких ошибок выводится в stderr как JSON.

Повторная команда с теми же исходниками даёт те же UUID и CAD-файлы; обновляются
только отчёты. Уже восстановленная схема не получает повторных проводов и меток.
Посторонние или изменённые CAD-файлы в каталоге результата не перезаписываются.

Для явного обновления оригиналов замените `--output-dir ...` на `--in-place`.
Перед этим сохраните и закройте редакторы. Создаются соседние резервные копии
`<имя>.before-recovery-<хэш исходного содержимого>.bak`. Повтор одинакового
содержимого не создаёт новые копии. Если запись одного файла завершается ошибкой,
уже записанные файлы возвращаются к прежнему содержимому. Это не атомарная
транзакция двух файлов при отключении питания; резервные копии остаются для отката.

Источники истины — входная PCB и существующие символы схемы. JSON/CSV и отчёты
пересоздаются командами выше, временные каталоги удаляются при завершении.
Каталог результата содержит один набор отчётов, без истории каждого запуска.
Резервные копии сохраняются для ручного отката; удаляйте их после принятия
результата. Сами скрипты не чистят другие проекты и чужие кэши.

## Границы и отказы

- Поддерживается один лист схемы. Иерархия явно отклоняется.
- Символы должны быть аннотированы и содержать определения в `lib_symbols`.
  UUID связи footprint с символом проверяется, если он задан в PCB.
- Существующие провода, метки и символы не удаляются. Связи между разными группами
  меди и совмещённые выводы остаются в схеме и перечисляются в отчёте. Остальные
  провода добавляются. Уже связанные выводы не получают повторных проводов.
- Маркер «не подключено» сохраняется: провод к нему пропускается с предупреждением.
  Изменённые ранее созданные объекты не дублируются; их нужно проверить вручную.
- При нескольких существующих именах одной группы используется первое по сортировке,
  остальные метки сохраняются и перечисляются для проверки. Это выбор подписи,
  а не предположение о назначении цепи.
- Новое замыкание из-за длины провода также попадает в отчёт; при необходимости
  уменьшите длину и повторите восстановление с исходной схемы.
- Раздельные площадки с одним номером вывода не объединяются автоматически.
- Заполненные зоны учитываются по сохранённым полигонам, без перезаливки.
  Незалитые зоны отклоняются. Целиком изолированные островки зоны без площадок
  и дорожек не являются отдельными строками таблицы выводов.
- Разные островки одной зоны не объединяют цепи. Если они относятся к разным
  восстановленным сетям, назначение цепей PCB пропускается с предупреждением:
  одна зона имеет одно имя сети. Схема и отчёты сохраняются, PCB копируется без
  изменений. Разделите зоны вручную и повторите назначение.
- Медные графические фигуры и текст, не участвующие в нативном графе связности,
  отклоняются. Изображения-образцы не считаются медью.
- Выводы схемы без соответствующих площадок перечисляются в отчёте; их
  соответствие безымянным площадкам не угадывается.
- Визуальная раскладка, ERC/DRC проекта, электрическое назначение, полярности и
  пригодность к производству не подтверждаются этим восстановлением.

Для плат без зон используются нативные непосредственные контакты и объединение
групп без повторного обхода всей платы для каждой цепи. Для плат с зонами
используется `GetConnectedItems` один раз на группу, чтобы сохранить различие
островков. Этот публичный API KiCad повторно обходит кластеры; время на больших
платах с множеством зон и цепей нужно измерять отдельно. Масштабирование на
сотни тысяч проводников пока не подтверждено.

## Проверки

```bash
PYTHONDONTWRITEBYTECODE=1 python3 -m unittest discover -s tests -p test_connectivity_recovery.py -v
```

Тесты используют реальные `pcbnew` и `kicad-cli`: все четыре поворота и зеркала,
многосекционный символ, переход между слоями, раздельные островки одной зоны,
ложные исходные назначения сетей, выдачу результата с совпадающими выводами и
замыканием концом длинного провода, продолжение работы в независимой группе,
маркер «не подключено», раздельные назначения PCB при лишних связях в схеме,
устаревшую/изменённую таблицу, резервную копию и повторное применение.
Эти проверки защищают от возврата к блокировке всего результата из-за локальной
проблемы схемы и от переноса её лишних связей в цепи PCB.
Проверяются также замена рабочего файла и точная исходная копия, отказ при изменении
исходников во время подготовки, откат при ошибке второй записи, сохранение проекта
для восстановления и повторное сохранение платы после синхронизации в памяти. Отдельная регрессия имитирует возврат старой
открытой платы из `LoadBoard`, синхронизирует её с изменённым файлом по тому же
пути и проверяет цепи после обычного сохранения редактором.
При отсутствии KiCad нативные тесты явно пропускаются, проверки чтения и записи
обычных файлов продолжают работать.
