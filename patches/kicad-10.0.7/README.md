# KiCad 10.0.7: сверка патчей

Проверено 25 октября 2026.

Последний стабильный выпуск — [10.0.7 от 7 октября](https://www.kicad.org/blog/2026/10/KiCad-10.0.7-Release/).
[10.0.8-rc1 от 22 октября](https://www.kicad.org/blog/2026/10/KiCad-Version-10.0.8-Release-Candidate-1-Available/)
является тестовым выпуском и не выбирается установщиком автоматически.

Исходники сверены с официальным репозиторием:

- тег `10.0.7`: `69cafb907ebc09e7722a2a464b1d466fc2e3608d`;
- вершина стабильной ветки `10.0`: `4e7360bc6f23f34a0de71f72a81c6f57ebf60cc6`;
- дополнительно просмотрены ключевые файлы ветки разработки `master`:
  `fb8beb88c27a860543205831f5d5a6aa79c67aca`.

## Состояние патчей

`series` задаёт порядок применения. Совместимые патчи переиспользуются из
10.0.4 и 10.0.5. Старые combined diff и standalone-патчи дублируют эти изменения
и не должны применяться поверх серии.

`plugins/library-panel/integration_patch.diff` — отдельный незавершённый шаблон
ручной интеграции с заголовками вида `@@ (constructor, ...)`, а не применимый
unified diff (`git apply --numstat` сообщает `corrupt patch`). Он не входит
в установочную серию; поддержку этого прототипа для 10.0.7 не заявляем.

| Патчи | Результат сверки |
| --- | --- |
| Исторический Altium null-byte | Уже исправлен upstream: конечный нулевой байт удаляется только для небинарных записей. |
| `0001` GOST interline | Не нужен: `GetInterline()` больше не делит целочисленные метрики шрифта. |
| `0002`, `0010..0017` | Группировка, колонки, компактный режим и сохранение состояния дерева остаются локальными расширениями. |
| `0003` | Фиксация курсора при drag-zoom остаётся актуальной. |
| `0004`, `0005` | Size X/Y и автоматический bus entry остаются локальными расширениями. |
| `0006` | Защита Reference от пустого значения базы всё ещё нужна. |
| `0007` | Дополнительные типы файлов в дереве проекта остаются локальным расширением. |
| `0008` | Фон листа остаётся локальным расширением; обновлён контекст `SCH_VIEW::DisplaySheet()`. |
| `0009`, `0018` | Боковая панель символов остаётся локальным расширением; `0009` обновлён с сохранением upstream-отписки от LocalHistory в деструкторе. |

Все 17 патчей последовательно применены с `patch --batch --forward --fuzz=0`
как к чистой 10.0.7, так и к указанной вершине `10.0`. Смещения строк допустимы,
отбрасывание контекста не потребовалось. Обновления `0008` и `0009` меняют
контекст, сохраняя прежнее локальное поведение.

Просмотр ключевых файлов `master` подтверждает, что исправления Altium/GOST
уже присутствуют, а рассмотренные локальные расширения не заменены upstream.
Это не проверка полной применимости или сборки серии на ветке разработки;
установщик нацелен на стабильную 10.0.7.

## Изменения установщиков

- Arch устанавливает пакеты через `pacman -Syu --needed`, обновляя базы вместе
  с системой и сохраняя подтверждение транзакции pacman. Это исправляет запрос
  удалённых пакетов 10.0.6 из устаревшей базы. После транзакции staged CLI снова
  проверяется до замены системных файлов, поскольку могли измениться зависимости.
- Arch автоматически выбирает эту серию как последнюю поддержанную.
  Для Debian/Ubuntu задавайте `--version 10.0.7` при обновлении с другой версии.
- Каталог без корректной `.meta`, соответствующей версии/хэшу/формату, и CLI
  больше не считается готовым кэшем. Формат кэша обновлён; старые сборки нужно пересобрать.
- До записи `.meta` проверяются версия CLI, код завершения и непустой результат
  импорта `Attiny-test.SchLib` и `test_bug_nullbyte.SchLib` с символами.
- Проверка после установки использует те же условия; отсутствие CLI и падение
  импорта теперь являются ошибками, а не предупреждениями.
- Патчи применяются неинтерактивно; обратное применение не выбирается автоматически.
- Проверяются аргументы версии, числа задач и несовместимые режимы.
- При отсутствующем/незавершённом кэше `--from-cache` останавливается до
  изменения системных пакетов или apt-источников.
- При сборке из архива Git не ищет версию в родительском репозитории этого проекта.
- Проверка runtime-пути различает каталог ресурсов в кэше и диагностические
  пути заголовков зависимостей (`__FILE__`), чтобы не отвергать корректную сборку.

## Воспроизведение

```bash
./scripts/build_and_install_arch.sh --version 10.0.7 --check
./scripts/build_and_install_ubuntu.sh --version 10.0.7 --check
python3 -m unittest discover -s tests -v

# На системе с зависимостями сборки:
./scripts/build_and_install_arch.sh --version 10.0.7 --build-only --rebuild
./scripts/build_and_install_arch.sh --version 10.0.7 --from-cache
```

Оба `--check` прошли на чистом архиве. Все 27 Python-тестов проекта прошли,
включая регрессии незавершённого кэша, повторного применения патча,
неверной версии CLI, ненулевого кода завершения и отсутствующего результата импорта.
Дополнительно проверено на CachyOS/Arch, GCC 16.2.1:

- полная Release-сборка всех модулей с Python/wxPython, OCC, SPICE и переводами;
- установка через `DESTDIR` в кэш, удаление отладочных символов;
- `kicad-cli version` → `10.0.7`;
- успешный импорт обоих `.SchLib` и синтетического примера в непустые `.kicad_sym`;
- повторное использование готового кэша публичным установщиком (`--build-only`).

Недостающие зависимости были распакованы в `cache/kicad-build-deps/root`,
без установки системных пакетов. При локальной проверке использовались
`LD_LIBRARY_PATH` для staged-библиотек и этих зависимостей, а также
`KICAD_STOCK_DATA_HOME` для ресурсов staged-дерева. Установщик теперь сам
задаёт путь к staged-ресурсам для проверки сборки.

Готовый кэш: `cache/kicad-arch-10.0.7-29f0d3dc8b2e`.
Логи: `cache/kicad-build-deps/{configure-final,build,build-final,install,smoke,tests}.log`.
Системная установка в `/usr` не выполнялась: sudo требует пароль.
Интерактивные действия в GUI не проверялись.
Проверка Ubuntu здесь ограничена режимом `--check` и тестами функций на Arch.

## Исправление тестовой библиотеки

Старая `tests/fixtures/test_bug_nullbyte.SchLib` не содержала обязательного
потока `FileHeader`. Отладчик подтвердил исключение в `ParseLibHeader()`:
импортер не доходил до бинарных PinFrac-записей. Исправлены CFB-контейнер и
генератор `tests/repro/create_minimal_test.py`; исходные `Data` и `PinFrac`
сохранены побайтно, что проверяется SHA-256 в тестах.

Также исправлен синтетический вариант генератора: после бинарного zlib-блока
не добавляется лишний строковый терминатор. Теперь конечный `0x00` действительно
принадлежит сжатым данным; его удаление ломает декомпрессию. Реальный импорт
синтетического файла проверен CLI. Старые установщики скрывали проблему
фикстуры, поскольку не завершались ошибкой при неуспешном импорте.

SHA-256 скачанного архива `kicad-10.0.7.tar.gz`:
`f0592c1348851e3e4917270f72443404fbc3a9a0daa60b2ed80419ce7ef45993`.

## Исправление аварии при закрытии редактора схем (28 октября 2026)

Патч `0019-symbol-sidebar-destruction-order.patch` исправляет обращение к уже
удалённому окну описания символа. В боковой панели ветка splitter с `m_details`
создаётся раньше ветки дерева и уничтожается первой. Затем деструктор
`LIB_TREE` пытается выполнить `m_details_ctrl->Unbind()` по недействительному
указателю. Два локальных аварийных дампа показали одинаковый стек:

```text
wxEvtHandler::GetNextDynamicEntry
wxEvtHandler::DoUnbind
LIB_TREE::~LIB_TREE
WX_SPLITTER_WINDOW::~WX_SPLITTER_WINDOW
SCH_SYMBOL_LIBRARY_PANE::~SCH_SYMBOL_LIBRARY_PANE
SCH_EDIT_FRAME::~SCH_EDIT_FRAME
```

Адрес возврата `_eeschema.kiface + 0x1c320f8` в исходной сборке соответствует
отписке от `wxEVT_HTML_LINK_CLICKED`. Build ID установленного модуля и
локального файла с символами совпал: `4602fa1f1e3bbb2705f888ab59f904744a699966`.

Теперь деструктор боковой панели синхронно удаляет `m_tree` после сохранения
настроек, пока окно описания и адаптер дерева ещё существуют. Отложенное
удаление здесь не подходит, поскольку зависимости уже были бы уничтожены.
Пересобираемый модуль — **`_eeschema.kiface`**; пересборка `libgit2` для этого
исправления не требуется. Дампы подтверждают сбой при закрытии.

Проверки: вся серия из 18 патчей применена к чистому архиву 10.0.7 через
`--check`; модуль пересобран; все 30 Python-тестов прошли; CLI новой сборки
возвращает `10.0.7` и успешно импортирует обе тестовые библиотеки Altium.
Эти проверки CLI не покрывают сохранение и закрытие окна редактора.
После установки пользователь подтвердил в GUI, что сохранение схемы и выход
работают; проверка включала повторное открытие сохранённой схемы.

Новый готовый кэш: `cache/kicad-arch-10.0.7-90f2781375ee`.
Предыдущий кэш `29f0d3dc8b2e` оставлен без изменений. Новая серия имеет другой
хэш, поэтому установщик не примет старый кэш за исправленную сборку.

На этом ПК обновлён `/usr/bin/_eeschema.kiface`; прежний установленный модуль
сохранён в `cache/kicad-sidebar-before-0019/_eeschema.kiface`.
SHA-256 исправленного установленного модуля:
`20172ac628fd42e1492c9ebacbeb13e812bda6cf5615727a11e6b39c85a35719`.

```bash

# На другом ПК после получения патча из Git:
./scripts/build_and_install_arch.sh --version 10.0.7 --rebuild
```

Повторить с открытой и скрытой боковой панелью символов.
